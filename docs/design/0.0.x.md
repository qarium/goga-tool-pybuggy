# Design Document: `pybuggy init` — генерация корневого `conftest.py` целевого проекта

Ветка `0.0.x`; документ сохранён как `docs/design/0.0.x.md`. Основание: архитектурный план
`docs/arch/0.0.x.md` (уже материализован в клеточную структуру стадией apply-architecture), задача из
`docs/proposals/0.0.x.md`.

Это **полная архитектурная спецификация реализации**: контракт (`CODEMANIFEST` ячейки
`goga_tool_pybuggy/commands/init`) уже изменён; документ детализирует **что и как** реализовать — без
исполнимого кода и без плана выполнения.

---

## Contract Changes

### Changed CODEMANIFEST Files

- `goga_tool_pybuggy/commands/init/CODEMANIFEST` — единственный изменённый манифест (4 правки из
  плана): Header `Annotations` (генерация conftest, overwrite gates, делегирование
  `write_pybuggy_conftest`); аннотация `run_init` (шаг 9 — conftest, шаг 10 — `Return 0`, новые
  Requirements/Constraints); новый тип `write_pybuggy_conftest(path: Path)`; Footer `Description`
  (дополнено предложение про генерацию conftest.py).

### New Entities

- `write_pybuggy_conftest(path: Path)` — Routine, `location: init.py`. Чистый (TTY-free) эмиттер
  корневого `conftest.py` целевого проекта из фиксированного захардкоженного шаблона; всегда
  (пере)записывает `path`, без проверки существования и без подтверждений.

### Changed Entities

- `run_init() -> exit_code:int` — сигнатура и `location` без изменений; аннотация расширена: новый
  шаг 9 (гейт + генерация `<cwd>/conftest.py`), шаг 10 (`Return 0`), новые Requirements
  (идемпотентность conftest-шага; лог ERROR + ненулевой exit при сбое записи) и Constraints (не
  генерировать conftest после сбоя/отмены более раннего шага; не мержить в существующий conftest).

### Deleted Entities

- Нет.

### Usages and Annotations Changes

- `goga_tool_pybuggy/commands/init/.usages/init.md` — добавлена секция «Генерация <cwd>/conftest.py»;
  conftest.py отражён в предметной области, артефактах первого запуска, идемпотентности, exit codes,
  программном usage (тесты) и побочных эффектах; удалена кросс-ссылка на `config-build.md`.
- `goga_tool_pybuggy/plugin/.usages/enable.md` — секция «Enable the plugin» приведена к генерируемому
  шаблону (`from dotenv import load_dotenv` → `plugin.install()`) + абзацы о порядке
  load_dotenv→install и автогенерации `pybuggy init`.
- `.goga/usages/cooks/click.md` — секция «Интерактивные запросы» (гейт перезаписи `confirm` с
  `default=False`, отказ = пропуск шага, не ошибка) — внесена earlier-стадией, зафиксирована как
  готовая.
- В Header CODEMANIFEST директива `Usages` не менялась: `conventions`, `click`, `ruamel-yaml`, `goga`
  покрывают новый код; новых внешних библиотек нет.

- Не зафиксировано. Phase 3 (gap-анализ, аудит консистентности по 4 измерениям) и Phase 4

## Entity Interaction and Data Flow

### Interaction Diagram

```
pybuggy CLI (root main, goga_tool_pybuggy)
  └─ init_cmd (click-обёртка, @click.command("init"), ctx.exit(rc))     [без изменений]
       └─ run_init (оркестратор: гейты + порядок шагов, exit code)
            ├─ шаг 2: run_goga_init (TTY, exit code, never raises)      [без изменений]
            ├─ шаг 3: build_pybuggy_config (TTY-seam, exit code)        [без изменений]
            │           └─ write_pybuggy_config (чистый YAML-эмиттер)   [без изменений]
            ├─ шаги 4–8: _discover_usages → копия .md → register_usages /
            │            register_annotations → _log_registration       [без изменений]
            └─ шаг 9: _write_root_conftest (private-хелпер, НОВЫЙ)
                 ├─ _should_rebuild(conftest, prompt)   — гейт перезаписи
                 │    └─ click.confirm(..., default=False)  [только если файл существует]
                 ├─ yes/absent → write_pybuggy_conftest(conftest)  (НОВЫЙ, чистый)
                 │    └─ <cwd>/conftest.py ← _CONFTEST_TEMPLATE (фикс. шаблон)
                 └─ no → logger.info(... step skipped, файл не тронут)
            шаг 10: return 0
```

### Data Flows

- **Поток 1 — генерация conftest (новый)**: `run_init` резолвит `cwd = Path.cwd()` →
  `conftest = cwd / "conftest.py"` (`Path`) → `_write_root_conftest(cwd)` → гейт
  `_should_rebuild` (файл отсутствует → True без промпта; существует → `click.confirm(default=False)`)
  → при записи `write_pybuggy_conftest(conftest)` → `path.parent.mkdir(parents=True, exist_ok=True)`
  → `path.write_text(_CONFTEST_TEMPLATE, encoding="utf-8")`. Результат: файл
  `<cwd>/conftest.py` с дословным шаблоном; управление возвращается в `run_init` → `return 0`.
- **Поток 2 — сбой записи**: `write_pybuggy_conftest` бросает `OSError` (не ловит — чистый писатель)
  → `_write_root_conftest`: `logger.error(...)` + `raise click.ClickException(str(e)) from e` →
  `run_init` не перехватывает → click печатает `Error: ...`, процесс завершается ненулевым кодом.
- **Поток 3 — отказ от перезаписи**: `click.confirm → False` → `logger.info("conftest overwrite
  declined, skipped", extra={"path": ...})` → `run_init` продолжает → `return 0`; файл не изменён.
- **Поток 4 — ранний отказ (существующее поведение, guarding нового шага)**: `run_goga_init`/
  `build_pybuggy_config` вернули ненулевой код → `run_init` делает ранний `return rc` ДО шага 9 —
  conftest не пишется; исключение bootstrap (шаги 4–7) → `click.ClickException` тоже ДО шага 9.

### Entity Dependencies

- Порядок материализации внутри `init.py` (leaf → root): константа `_CONFTEST_TEMPLATE` → Routine
  `write_pybuggy_conftest` → private-хелпер `_write_root_conftest` (использует `_should_rebuild` и
  `write_pybuggy_conftest`) → оркестратор `run_init` (шаг 9 вызывает хелпер) → фасад
  `__init__.py` (экспорт `write_pybuggy_conftest` в import + `__all__`, алфавитно после
  `write_pybuggy_config`).
- Контрактных зависимостей не добавляется: `Imports` манифеста не меняются (`SpecEntry`/`GitEntry`/
  usage `configuration` из `goga_tool_pybuggy/config`; `PluginConfigKeys` из
  `goga_tool_pybuggy/plugin`). Шаблон ссылается на `goga_tool_pybuggy.plugin.install()` только как
  **текст**, записываемый в проект потребителя, — не как импорт кода. Карта зависимостей
  (`goga schema`): `config` + `plugin` → `commands/init` →(`init_cmd`)→ `goga_tool_pybuggy` (root) —
  без изменений, циклов нет.

## Code Stack Trace

### Trace: `run_init()` (изменённый входной контрактный пункт)

#### Chain

1. **Input**: вызов из `init_cmd` (`ctx.exit(run_init())`) или прямой программный вызов из тестов.
   Параметров нет; корень вывода — `Path.cwd()`; TTY — для гейтов `click.confirm`.
2. **Step**: `cwd = Path.cwd()`; `goga_config = cwd/.goga/config.yml`;
   `pybuggy_config = cwd/.goga/tools/pybuggy/config.yml` → checkpoint: пути `Path`, типы совпадают с
   ожиданиями `_should_rebuild(path: Path, prompt: str)`. **passed**
3. **Step** (шаг 2): гейт goga-конфига `_should_rebuild(goga_config, ...)` — отсутствует → `True`
   (без промпта); существует → `click.confirm(default=False)`; при `True` → `rc = run_goga_init()`;
   `rc != 0` → ранний `return rc` → checkpoint: `run_goga_init() -> int`, never-raises контракт
   соблюдён. **passed**
4. **Step** (шаг 3): гейт pybuggy-конфига `_should_rebuild(pybuggy_config, ...)`; при `True` →
   `rc = build_pybuggy_config()`; `rc != 0` → ранний `return rc` → checkpoint: новый шаг 9 при
   раннем возврате недостижим — Constraint «не генерировать conftest после сбоя/отмены более раннего
   шага» выполняется структурой управления. **passed**
5. **Step** (шаги 4–7): `try:` `_discover_usages(importlib.resources.files("goga_tool_pybuggy.api"))`
   → `list[tuple[stem, text]]`; копия каждого в `<cwd>/.goga/usages/cooks/pybuggy/<stem>.md`;
   `register_usages(...)` → `added_keys`; `register_annotations(...)` → `added_keys`; `except
   (OSError, YAMLError, ValueError)` → `click.ClickException` → checkpoint: без изменений; исключение
   прерывает команду ДО шага 9 (conftest не пишется). **passed**
6. **Step** (шаг 8): `_log_registration(...)` — INFO для добавленных, WARNING для пропущенных. →
   checkpoint: без изменений. **passed**
7. **Step** (шаг 9, НОВЫЙ): `_write_root_conftest(cwd)` → внутри: `conftest = cwd / "conftest.py"`
   (`Path`) → гейт `_should_rebuild(conftest, "conftest.py exists — overwrite it?")` →
   absent/yes → `write_pybuggy_conftest(conftest)`; no → `logger.info(...)`, файл не тронут →
   checkpoint type-flow: `Path` → `path: Path` (совпадение сигнатур); click.Abort из `confirm`
   не ловится (`except OSError` его не перехватывает) и распространяется как в гейтах шагов 2–3
   (click печатает `Aborted!`, exit 1). **passed**
8. **Step** (шаг 10, НОВЫЙ): `return 0` → checkpoint: все обязательные шаги либо выполнены, либо
   явно пропущены по отказу пользователя. **passed**
9. **Output**: `exit_code:int` — 0 (успех, включая пропуски по отказам) / ненулевой код goga или
   конфиг-билда / ненулевой exit из `ClickException` (bootstrap или запись conftest).

#### Checkpoint Summary

- Тип-поток `run_init` → `write_pybuggy_conftest`: `Path` → `path: Path` — passed.
- Аллокация ответственности «гейт в оркестраторе, запись в pure-писателе» — симметрична существующим
  парам (`run_init` → `build_pybuggy_config` → `write_pybuggy_config`) — passed.
- Порядок шагов соответствует аннотации (лог — шаг 8, conftest — шаг 9, `return 0` — шаг 10) —
  passed.
- Обработка `click.Abort` на conftest-гейте — единообразна с гейтами шагов 2–3 — passed.

### Trace: `write_pybuggy_conftest(path)` (новый входной контрактный пункт)

#### Chain

1. **Input**: `path: Path` — целевой `<cwd>/conftest.py` (от `run_init`/`_write_root_conftest`) или
   произвольный путь в тестах/программном вызове. TTY не требуется.
2. **Step 1**: `path.parent.mkdir(parents=True, exist_ok=True)` — родитель гарантирован (для
   `<cwd>/conftest.py` уже существует; `exist_ok` делает рутину безопасной для вложенных путей) →
   checkpoint: симметрично шагу 6 `write_pybuggy_config`. **passed**
3. **Step 2**: `path.write_text(_CONFTEST_TEMPLATE, encoding="utf-8")` — безусловная перезапись →
   checkpoint: нет ни одной ветки проверки существования/подтверждения — соответствует Constraint
   «always overwrite `path` on every call»; `OSError` намеренно распространяется к вызывающему
   (паттерн `install_pybuggy`: «An I/O error during read/write propagates to the caller»). **passed**
4. **Output**: `None` (Routine без выходного значения — процедура); побочный эффект — файл
   `path` с дословным содержимым `_CONFTEST_TEMPLATE`:

   ```python
   from dotenv import load_dotenv

   load_dotenv()

   from goga_tool_pybuggy import plugin

   plugin.install()
   ```

#### Checkpoint Summary

- Содержимое шаблона совпадает дословно в трёх источниках: аннотация `write_pybuggy_conftest`
  (CODEMANIFEST), `init.md` (секция «Генерация <cwd>/conftest.py»), `enable.md` (секция «Enable the
  plugin») — passed.
- Порядок операторов шаблона корректен против реального API: `load_dotenv()` (без аргументов,
  `override=False`) до `from goga_tool_pybuggy import plugin` + `plugin.install()` — опции плагина
  резолвятся из `os.environ`, поэтому `.env` должен быть загружен раньше; `goga_tool_pybuggy.plugin`
  реально экспортирует `install` (`plugin/__init__.py`: `__all__ = ["ApiPlugin",
  "PluginConfigKeys", "install"]`, `install(**kwargs)` без обязательных аргументов) — passed.
- Зависимости потребителя: `python-dotenv>=1.2.2` уже в `pyproject.toml`; `goga_tool_pybuggy`
  присутствует по определению (файл генерирует сам pybuggy). Проверка импортируемости окружения
  потребителя сознательно не выполняется (Constraint: отсутствие проявится при запуске pytest) —
  passed.
- Доступность `plugin.install()` как атрибута подмодуля: шаблон импортирует модуль
  (`from goga_tool_pybuggy import plugin`) и вызывает `plugin.install()` — соответствует
  документированному в `enable.md` способу включения — passed.

## Algorithm Design

### `_CONFTEST_TEMPLATE` (module-level constant)

**Responsibility**: единственный источник текста корневого conftest; фиксируется дословно, как
`_INSTALL_LINE` для Dockerfile-строки. Строковый литерал, собираемый конкатенацией с явными `\n`
(7 строк: 4 кода + 3 пустые), с завершающим `\n` (конвенция текстовых файлов; тот же паттерн, что у
`_INSTALL_LINE`).

```python
_CONFTEST_TEMPLATE = (
    "from dotenv import load_dotenv\n"
    "\n"
    "load_dotenv()\n"
    "\n"
    "from goga_tool_pybuggy import plugin\n"
    "\n"
    "plugin.install()\n"
)
```

**Errors**: нет (константа).

**Edge Cases**: нет — детерминирована, без параметризации/плейсхолдеров/резолвинга версий.

### `write_pybuggy_conftest(path: Path) -> None`

**Responsibility**: чистый эмиттер корневого conftest.py потребителя; изолирует запись от гейтов и
TTY, тестируется напрямую.

**Algorithm:**
```
1. path.parent.mkdir(parents=True, exist_ok=True)
   → родительский каталог существует
2. path.write_text(_CONFTEST_TEMPLATE, encoding="utf-8")
   → файл path перезаписан дословным шаблоном (безусловно, на каждом вызове)
```

**Errors:**
- `OSError` → не ловится, распространяется к вызывающему (`_write_root_conftest` логирует ERROR и
  мапит в `click.ClickException`) → потребитель видит ненулевой exit команды `pybuggy init`.

**Edge Cases:**
- существующий файл → молча перезаписывается (проверка существования — не здесь);
- вложенный путь (`tmp_path/"nested"/"conftest.py"`) → каталог создаётся шагом 1;
- пустой TTY-контекст → не влияет: ни одного вызова `click.*` внутри рутины.

**Дополнения по `conventions`**: Google-docstring (`Args` для `path`; `Returns`/`Raises` —
`OSError`); без логгинга внутри (чистый детерминированный эмиттер — зеркально
`write_pybuggy_config`); тайп-хинты PEP 604/`pathlib.Path`.

### `_write_root_conftest(cwd: Path) -> None` (private-хелпер шага 9)

**Responsibility**: инкапсулирует шаг 9 `run_init` — гейт перезаписи, запись, INFO-лог на отказ,
ERROR-лог + ClickException на сбой; выделяется из `run_init` по установленному в ячейке паттерну
(`_should_rebuild`, `_log_registration`), сохраняя mccabe-сложность оркестратора с запасом к капу
10.

**Algorithm:**
```
1. conftest = cwd / "conftest.py"
2. TRY:
   a. IF _should_rebuild(conftest, "conftest.py exists — overwrite it?"):
      - absent → True (без промпта)
      - exists → click.confirm(..., default=False)
      → True: write_pybuggy_conftest(conftest)      # перезапись/создание
      → False: logger.info("conftest overwrite declined, skipped",
                           extra={"path": str(conftest)})   # файл не тронут
3. EXCEPT OSError as e:
   → logger.error("conftest write failed", extra={"path": str(conftest), "error": str(e)})
   → raise click.ClickException(str(e)) from e
```

**Errors:**
- `OSError` (запись) → ERROR-лог + `click.ClickException` → ненулевой exit, единообразно с остальными
  шагами;
- `click.Abort` (Ctrl-C на confirm) → не ловится (`except OSError`) → распространяется как в гейтах
  шагов 2–3 → click `Aborted!`, exit 1.

**Edge Cases:**
- файл существует и пользователь отказал → INFO, файл нетронут, команда продолжает шаг 10 (`return 0`)
  — повторный запуск идемпотентен;
- файл существует и пользователь согласился → полная перезапись шаблоном (без мержа);
- файл отсутствует → запись без единого промпта.

### `run_init() -> exit_code:int` (изменённая часть)

**Responsibility**: оркестратор команды; добавляется вызов `_write_root_conftest(cwd)` между
`_log_registration(...)` (шаг 8) и `return 0` (шаг 10). Docstring обновляется с «Algorithm (9
steps)» на 10 шагов: добавляется описание шага 9 (гейт/запись/отказ) и упоминание conftest в
`Raises` (`click.ClickException` — file-write/YAML/navigation/bootstrap **или conftest-write**
failure).

**Algorithm (дельта):**
```
... шаги 1–8 без изменений ...
8.5. _write_root_conftest(cwd)        # НОВЫЙ шаг 9
9.  return 0                          # бывший шаг 9 → шаг 10
```

**Errors:** без изменений для шагов 1–8; новый — `OSError` записи conftest (через хелпер, ERROR +
`ClickException`).

**Edge Cases:** повторный запуск с отказом на conftest-гейте → файл не изменён, exit 0.

### `__init__.py` фасада ячейки (изменение)

Добавить `write_pybuggy_conftest` в импорт-блок из `.init` и в `__all__` (алфавитный порядок —
после `write_pybuggy_config`): контрактная публичность рутины для потребителей и тестов.

## Cross-cutting Concerns

- **Error handling**: глобальная стратегия ячейки не меняется. Интерактивные шаги возвращают код и
  никогда не бросают (`run_goga_init`, `build_pybuggy_config`); `run_init` ранним `return`
  распространяет их код ДО нового шага. Ошибки ФС/YAML мапятся в `click.ClickException` (ненулевой
  exit через click) — новый conftest-шаг следует той же стратегии, плюс явный `logger.error` перед
  рейзом (требование контракта). `click.Abort` на confirm-гейтах не перехватывается — click
  завершает процесс кодом 1.
- **Logging**: `logging` + структурные `extra` (`conventions`). Новые события: INFO
  `conftest overwrite declined, skipped` (`extra={"path": ...}`) — отказ пользователя, шаг пропущен;
  ERROR `conftest write failed` (`extra={"path": ..., "error": ...}`) — операция не может быть
  завершена. Успешная запись не логируется (единообразно с `write_pybuggy_config`/
  `build_pybuggy_config`; контракт INFO требует только на отказ). Сообщения lowercase, стабильные
  event-имена.
- **Validation**: новой валидации нет — шаблон фиксирован, параметров нет; «Validation» гейта —
  единственная проверка существования файла, делегирована `_should_rebuild`.
- **Caching**: не применяется (однократная CLI-команда).
- **Concurrency**: однопоточная CLI; требований потокобезопасности нет.

## Usages Analysis

### `conventions`
- **What it provides**: обязательные правила Python-кода: относительные импорты внутри пакета,
  Google-docstring, `logging` + структурные `extra`, форматирование, тест-структура
  (`tests/commands/init/test_init.py`, `test_<what>_<scenario>`, tmp_path для ФС, прямые вызовы
  handler-ов), команды валидации (`pytest tests/ -x`, `ruff check`).
- **Where used**: `write_pybuggy_conftest`, `_write_root_conftest`, `run_init` (дельта), фасад
  `__init__.py`, все новые тесты.
- **Why chosen**: обязательная корневая практика проекта; подключена файлом
  `.goga/usages/conventions.md`.
- **How exactly**: docstring с `Args`/`Raises`; `logger = logging.getLogger(__name__)` уже в модуле;
  `pathlib.Path` вместо строковых путей (правило PTH в ruff); тесты — прямые вызовы, ФС только через
  `tmp_path`, моки — только на внешних границах (TTY-стабы `run_goga_init`/
  `build_pybuggy_config`, `click.confirm`).

### `click`
- **What it provides**: API обёрток, `confirm`/`prompt` (включая паттерн гейта перезаписи
  `default=False`), маппинг доменных ошибок в `click.ClickException`.
- **Where used**: `_write_root_conftest` (`click.confirm` гейт + `ClickException`), `run_init`
  (существующие гейты), `init_cmd` (обёртка, без изменений).
- **Why chosen**: третья confirm-точка команды обязана быть единообразной с гейтами конфигов;
  обновлённая секция «Интерактивные запросы» описывает ровно этот случай.
- **How exactly**: `click.confirm("conftest.py exists — overwrite it?", default=False)` — через
  существующий `_should_rebuild(path, prompt)`; отказ — не ошибка (пропуск шага, exit 0); `OSError`
  → `click.ClickException(str(e)) from e`.

### `ruamel-yaml`
- **What it provides**: round-trip YAML (`CommentedMap`, `LiteralScalarString`, preserve_quotes).
- **Where used**: только существующие `write_pybuggy_config`, `register_usages`,
  `register_annotations` — новым сущностям не нужна (запись plain-text файла).
- **Why chosen**: зафиксирована как используемая практика манифеста; для нового кода —
  неприменима и не подключается.
- **How exactly**: без изменений.

### `goga`
- **What it provides**: in-process Python-API инициализации goga-проекта
  (`goga.onboarding.Questionnaire` per-field + `FileGenerator.generate`).
- **Where used**: только `run_goga_init` (без изменений данной правкой).
- **Why chosen / How exactly**: без изменений.

### Imported Usages
- `configuration` из `goga_tool_pybuggy` → `goga_tool_pybuggy/config` — схема
  `.goga/tools/pybuggy/config.yml` для `write_pybuggy_config` (без изменений данной правкой).
  - Path: `goga_tool_pybuggy/config/.usages/configuration.md`
- Импортированные usages из `goga_tool_pybuggy/plugin` отсутствуют (импортируется только тип
  `PluginConfigKeys`); текстовый референс шаблона на `plugin.install()` — не контрактная связь.
