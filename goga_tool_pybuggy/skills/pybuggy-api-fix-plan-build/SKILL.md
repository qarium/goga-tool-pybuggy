# Pybuggy API Fix Plan — Build

## Идентичность

Ты собираешь пункты плана исправлений из классификации анализа, группируешь их по клеткам и согласуешь с пользователем.

## Алгоритм

### Шаг 1. Прочитай артефакт анализа

Таблица «Классификация»: тест | класс | основание | решение пользователя | план-направление.

### Шаг 2. Сгруппируй падения по клеткам

Клетка `tests/<spec>/<id>/` + класс → один пункт `FIX-<N>` (несколько падений одной клетки с одним классом — один
пункт). Разные классы в одной клетке — отдельные пункты.

### Шаг 3. Назначь тип и действия по классу

| Класс         | Тип пункта                                           | Действия                                                                                                    | Проверка                                               |
|---------------|------------------------------------------------------|-------------------------------------------------------------------------------------------------------------|--------------------------------------------------------|
| `spec-drift`  | `regen-artifacts` → `update-routine` → `update-test` | `goga tool pybuggy endpoint generate <endpoint-id> -f`; аннотация Routine в CODEMANIFEST под новый контракт | `endpoint diff` пуст; `goga lint` клетки; rerun тестов |
| `case-defect` | `update-routine` → `update-test`                     | аннотация Routine под спеку; тест по новой аннотации                                                        | `goga lint` клетки; rerun                              |
| `test-defect` | `update-test`                                        | правка `test_*.py` по аннотации Routine                                                                     | rerun теста                                            |
| `service-bug` | `record-bug`                                         | запись `BUG-<feature>-<N>` в `docs/bugs/<feature>.md` (описание, шаги, traceback — из досье анализа)        | запись создана; тест остаётся красным                  |
| `environment` | `restore-env`                                        | действия по диагнозу (SUT/env/conftest)                                                                     | rerun затронутых тестов                                |

### Шаг 4. Проставь порядок исполнения

Артефакты → Routine → тесты → баги/окружение.

### Шаг 5. Утверди план — WAIT

Представь план; спроси пользователя: утвердить / скорректировать. Итерации до утверждения.

### Шаг 6. Сформируй [FIX_PLAN_ITEMS]
