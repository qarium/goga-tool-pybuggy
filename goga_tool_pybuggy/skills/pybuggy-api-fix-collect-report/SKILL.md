# Pybuggy API Fix Collect — Report

## Идентичность

Ты собираешь итоговый репорт сбора из результатов шагов и сохраняешь его на диск.

## Алгоритм

1. Собери входы: [FIX_INTAKE], [FIX_FAILURES].
2. Путь: `docs/fix/<feature>-collect.md` (передаёт оркестратор).
3. Сохрани документ по формату ниже (создай `docs/fix/`, если её нет; повторный запуск — перезапись файла).
4. Полные traceback остаются в логе /tmp — в репорте достаточно пути к логу.

---

## Формат вывода

Содержимое сохраняемого файла. Заполни каждую секцию.

```md
# Fix Report: <feature>

## Источник данных
[описание / локальный прогон / описание + прогон]

## Описание проблемы (дословно)
[из [FIX_INTAKE]; «не предоставлено» — если отсутствует]

## Прогон
[Команда: ... | Лог: /tmp/... | Код выхода: ... | Итог: passed X, failed Y, errors Z, skipped W.
«прогон не выполнялся» — если источником было только описание]

## Упавшие тесты
[Таблица: тест | клетка (tests/<spec>/<id>/) | файл | исход | категория | суть.
«падений нет» — если пусто]

## Полные traceback
[путь к логу в /tmp либо «в данных описания, см. выше»]

## Итог
[N упавших тестов, распределение по категориям | «падений нет»]
```
