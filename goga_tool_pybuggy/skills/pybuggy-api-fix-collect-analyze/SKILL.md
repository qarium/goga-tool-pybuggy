# Pybuggy API Fix Collect — Analyze

## Идентичность

Ты разбираешь данные о падениях (лог прогона `docs/fix/<feature>-log.txt` или данные из описания): извлекаешь упавшие тесты и категоризируешь
ошибки по характеру сбоя.

## Алгоритм

### Шаг 1. Возьми данные о падениях

1. В [FIX_INTAKE] выполнен прогон — читай лог по записанному пути (полный вывод).
2. Прогона нет — данные о падениях из описания в [FIX_INTAKE].

### Шаг 2. Извлеки падения

Для каждого FAILED/ERROR/SKIPPED из вывода зафиксируй:

- тест `test_<name>`, файл `tests/<spec>/<id>/test_<name>.py`, клетка `tests/<spec>/<id>/`;
- исход: FAILED / ERROR / SKIPPED;
- суть: expected vs actual из assert; для ERROR — первые строки traceback; для SKIPPED — причина скипа
  (skip-маркер, условие, `xfail`) — замаскированное падение, разбирается наравне с остальными.

### Шаг 3. Категоризируй ошибки

Техническая классификация по характеру сбоя:

| Категория             | Признак                                                  |
|-----------------------|----------------------------------------------------------|
| `assertion`           | проверка не сошлась: expected ≠ actual                   |
| `error-before-assert` | до ассерта: import, fixture, collection, materialization |
| `connection-env`      | connection refused, timeout, DNS, недоступность SUT      |
| `skip-masking`        | `pytest.skip`, skip-маркеры, `xfail` в выводе            |
| `other`               | не подходит ни под одну выше                             |

### Шаг 4. Сформирай [FIX_FAILURES]

STOP:

- данных о падениях нет вовсе: прогон не выполнялся, в описании данных нет.

0 падений и замаскированных — зафиксируй «падений нет».

---

## Формат вывода

Заполни каждую секцию. Пустые секции запрещены.

```md
# [FIX_FAILURES]

## Источник разбора

[лог `docs/fix/<feature>-log.txt` либо данные из описания]

## Сводка прогона

[passed / failed / errors / skipped]

## Упавшие тесты

[Таблица: тест | клетка (tests/<spec>/<id>/) | файл | исход (FAILED/ERROR/SKIPPED) | категория | суть.
«падений нет» — если пусто]

## Распределение по категориям

[Категория → количество тестов]

## Замечания

[неоднозначные строки вывода, требующие внимания. Пусто, если нет]
```
