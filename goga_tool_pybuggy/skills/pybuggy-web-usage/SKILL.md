# Pybuggy Web Runtime Usage

## Purpose

Скилл предоставляет документацию по веб-рантайму pybuggy — фикстуре `web` (pybuggy-web): браузерные
UI-тесты, в которых каждый шаг — предложение на естественном языке, превращаемое в Playwright-код
LLM один раз и кешируемое рядом с тестом. Этот скилл — единственный источник контекста о реальном
веб-API pybuggy.

Другие скиллы и задачи (стадии дизайна тестов, кодогенерации, приёмки) вызывают этот скилл, чтобы
получить актуальный референс. Референс основан на cooks-файле проекта, а не на догадках.

---

## Behavior

1. Проверь файл `.goga/usages/cooks/pybuggy/pybuggy-web.md`. Если файла нет или он пуст — веб-документация
   не загружена: попроси пользователя запустить `goga tool pybuggy init` (kind `web` или `both`; команда
   копирует документацию веб-рантайма и регистрирует ключ `pybuggy-web` в `.goga/config.yml`), и остановись.

2. Прочитай файл целиком. Файл соответствует usage-ключу `pybuggy-web`.

3. Если передан `$ARGUMENTS` (тема: `web` или иная), используй только релевантные теме части; иначе —
   весь файл.

4. Примени прочитанное к контексту вызывающего скилла: фикстура `web` (активация документом
   `.goga/tools/pybuggy/web.yml`), `web.step(sentence)` — шаг-действие, `web.expect(sentence)` — шаг-проверка
   (поллинг до истинности), `web.group(...)` — блок мини-сценария: набор тесно связанных действий,
   меняющий состояние страницы/виджета; промпт группы называет достигаемое состояние, лечение
   группы — целиком (диагноз по всем шагам, регенерация ряда), `run_on_page(...)`; захваты
   переменных — маркер `{% var <имя> %}` внутри предложения шага захватывает значение со страницы,
   маркер `{{ <имя> }}` в последующих предложениях (шагах и проверках) подставляет захваченное
   значение; захват — только для динамики страницы (значений, неизвестных при написании теста),
   статические литералы пишутся без маркеров; полные URL в шагах (без base_url-шаблонизации);
   один шаг = одно действие; кеш шагов рядом с тестом (`tests/<path>/<test_name>/`), коммитится в репозиторий;
   режимы `--strict-mode` (0 LLM-вызовов, cache-miss = падение; для CI и повторных прогонов),
   `--interactive` (интерактивное лечение шагов), `--browser-endpoint ws://…|http://…`; **секреты в
   предложениях шагов запрещены** (всё попадает в промпт провайдера и в репозиторий). Используй только
   фактическое содержимое файла как источник — не выдумывай детали API. Не пересказывай файл дословно —
   дай применимый референс.

5. Укажи путь к файлу, чтобы вызывающий мог прочитать полные детали при необходимости.
