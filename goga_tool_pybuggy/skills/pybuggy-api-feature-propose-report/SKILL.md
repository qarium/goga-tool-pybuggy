## Identity

Ты отвечаешь за синтез финального артефакта из всех предшествующих шагов и его сохранение в файл.

## Algorithm

1. Собрать выходы всех шагов: [INTAKE_REPORT], [DISCOVERY_REPORT], [ELABORATION_REPORT].
2. Синтезировать единый артефакт [FEATURE_SPEC].
3. Включать только проверенные факты (из спеки и подтверждённые пользователем) — без догадок.
4. Проверить полноту: каждая секция заполнена.
5. Сохранить [FEATURE_SPEC] в `docs/pybuggy/feature-requirements.md` (создать директорию `docs/pybuggy/`,
   если отсутствует; перезаписать файл при повторном запуске).

---

## Output Format

Сохрани результат в `docs/pybuggy/feature-requirements.md`. Содержимое файла соответствует формату ниже.
Заполни каждую секцию. Пустые секции запрещены.

```md
### Детальные требования для фичи: [Название фичи]

**1. Контекст и цель:**

- **Сервис:** [Краткое описание сервиса]
- **Цель фичи:** [Уточнённая цель]

**2. Эндпоинты фичи:**

[Таблица: endpoint-id | spec | method | path | роль в фиче]

Пути сгенерированных артефактов:

- фикстура: `api/<spec>/<id>/api.py` (имя фикстуры, модель `Request`)
- схемы: `api/<spec>/<id>/schemas/<status>.json`
- каталог тестов: `tests/<spec>/<id>/`

**3. Функциональные требования:**

- **Основные сценарии (positive):**
    1. [Сценарий: предусловие → действие → ожидаемый успех]
- **Негативные сценарии (negative):**
    1. [Сценарий: невалидный ввод / нет прав → ожидаемая ошибка]
- **Критерии приёмки:**
    - [Критерий]
- **Ограничения и границы:** [Что фича не делает]

**4. Матрица сценариев:**

[Таблица: сценарий | тип (positive/negative) | предусловие/статус | эндпоинты | severity]

**5. Данные и предусловия:**

- Валидные данные: [...]
- Невалидные данные: [...]
- Дата-сетап (сущности/роли/фабрики): [...]
- Окружение (env/version): [...]

**6. Контракты ответов:**

[Таблица: сценарий | статус-код | ключевые поля для asserts | инварианты]

**7. Роли и доступы:**

[Кто может / не может вызывать эндпоинты]

**8. Интеграционные аспекты:**

- [Взаимодействие с другими компонентами, моки, внешние зависимости]

**9. Ссылки и ресурсы:**

- [Спеки (location), дизайн, API-док и т.д.]

**10. Пользовательские библиотеки:**

[Таблица: ключ | библиотека | назначение (данные/моки/утилиты) | где используется (endpoint-id / сценарий)].
Ключ — короткое имя usage (файл `.goga/usages/cooks/<ключ>.md` создаётся на этапе cells). Секция **опциональна**:
если фича не использует библиотеки подготовки данных/моков/утилит — указать «нет» (как §8).
```
